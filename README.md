# Інфраструктура для ML-сервісів на AWS EKS

Цей проєкт містить Terraform-код для автоматичного розгортання масштабованої та безпечної інфраструктури в AWS. Він створює віртуальну приватну мережу (VPC) та керований Kubernetes-кластер (EKS) з двома групами робочих вузлів (CPU та GPU), що є ідеальною основою для розгортання та керування ML-сервісами.

Проєкт дотримується найкращих практик "Інфраструктура як код" (IaC) і має модульну структуру для легкої підтримки та розширення.

## Архітектура

Створюється така архітектура:

- **VPC** з публічними та приватними підмережами у трьох зонах доступності для високої надійності
- **NAT Gateway** у публічній підмережі, щоб надати ресурсам у приватних підмережах доступ до Інтернету
- **EKS Control Plane**, що керується AWS
- **Дві групи робочих вузлів** (Managed Node Groups), розміщені в приватних підмережах для підвищеної безпеки:
  - `cpu_nodes`: для загальних обчислювальних завдань (наприклад, t3.micro)
  - `gpu_nodes`: для інтенсивних ML-завдань (наприклад, g4dn.xlarge)

## Передумови

Перед початком роботи переконайтесь, що у вас встановлено:

- **AWS Account** з налаштованими правами доступу
- **Terraform** (версія 1.5.0+)
- **AWS CLI** (версія 2+), налаштований через `aws configure`
- **kubectl** для взаємодії з кластером
- **S3-бакет** в AWS для зберігання стану Terraform

## Налаштування та розгортання

### 1. Налаштування S3-бекенду

Перед першим запуском вам потрібно вказати назву вашого S3-бакета. Відредагуйте три файли:

- `backend.tf` (у корені)
- `vpc/backend.tf`
- `eks/backend.tf`

Змініть рядок `bucket` на назву вашого бакета:

```terraform
terraform {
  backend "s3" {
    bucket = "your-unique-bucket-name"  # <-- ВКАЖІТЬ НАЗВУ ВАШОГО БАКЕТА
    # ...
  }
}
```

### 2. Розгортання інфраструктури

Виконуйте всі команди з кореневої директорії проєкту:

```bash
# Ініціалізація проєкту та завантаження модулів
terraform init

# Створення інфраструктури (процес займає 15-20 хвилин)
terraform apply
```

Після підтвердження (`yes`) Terraform почне створювати всі необхідні ресурси.

### 3. Підключення до кластера

Після успішного створення інфраструктури налаштуйте kubectl для роботи з новим кластером:

```bash
# Отримайте назву кластера та регіон з виводу terraform apply
# або з файлу variables.tf
aws eks --region <your_aws_region> update-kubeconfig --name <your_cluster_name>

# Перевірка підключення та статусу робочих нод
kubectl get nodes
```

## Очищення ресурсів

**Дуже важливо!** Щоб уникнути непередбачуваних витрат, обов'язково знищуйте інфраструктуру, коли вона більше не потрібна:

```bash
# Ця команда видалить усі ресурси, створені через Terraform
terraform destroy
```

## Вихідні дані (Outputs)

Після виконання `terraform apply` проєкт виводить такі дані:

- **eks_cluster_name**: Назва вашого EKS-кластера
- **eks_cluster_endpoint**: Адреса API-сервера для підключення до кластера
- **vpc_id**: Ідентифікатор створеної віртуальної мережі (VPC)
